### Step 6: chained-call count for a liquidate-shaped transaction: DONE

- `MAX_NUMBER_CHAINED_CALLS = 10` (`lee/state_machine/src/state/mod.rs:21`, and again in `lee/state_machine/core/src/program/mod.rs:14`). The brief's path `lee/state_machine/src/validated_state_diff/mod.rs` only *uses* it.
- **Semantics (read from the code, not just the constant):** the public path (`validated_state_diff/mod.rs`) does `ensure!(chain_calls_counter <= MAX)` at the top of each loop iteration and increments after each execution, so calls with counter 0..=10 run: **a public transaction may execute at most 11 programs (1 top-level + 10 chained)**. The existing test `execution_fails_if_chained_calls_exceeds_depth` uses MAX+1 chained calls (12 executions) and expects `MaxChainedCallsDepthExceeded`. The **privacy-preserving host path** (`privacy_preserving_transaction/circuit/mod.rs:107`) uses `chain_calls_counter >= MAX`, so a private transaction may execute at most **10** programs. Plan for 10 if any step must be private-capable.
- Test: `spikes/s1/chain_count.rs` is appended to a copy of `programs/integration_tests/tests/stablecoin.rs` (reuses its fixtures) as `tests/chain_count.rs`, with `risc0-zkvm = { workspace = true }` added to the scratch `integration_tests/Cargo.toml` (this also modified the scratch `lez-programs/Cargo.lock`; `git status` there shows `M Cargo.lock`, `M programs/integration_tests/Cargo.toml`, plus untracked `tests/chain_count.rs` and `examples/global_pdas.rs`). The appended file was byte-identical to `spikes/s1/chain_count.rs`; the temporary copy `~/lez-spikes/s1/chain_count_addendum.rs` was a leftover and has been deleted. It builds the real state with `state_for_stablecoin_tests()`, runs `open_position` and `withdraw_collateral` as **real `transition_from_public_transaction` calls** (they succeed), and, for each, replays the call chain breadth-first with the risc0 executor exactly as `Program::execute` does (inputs written in the same order), printing one line per program execution with `info.cycles()`.

- **Stand-in caveat:** there is no hook program yet, so the liquidate-shaped chain is *modelled*: hook (1 execution, cycles unknown) -> chained `Token::InitializeAccount` on the winner's holding (1 execution, 104,936 cycles) and chained stablecoin `withdraw_collateral` (1 execution, 626,902 cycles) which itself chains one `Token::Transfer` (1 execution, 133,827 cycles). The public-execution cycle cap is `MAX_NUM_CYCLES_PUBLIC_EXECUTION = 32 Mi` per program execution (`lee/state_machine/src/program/mod.rs`), so per-execution headroom is more than 50x.

- Nix setup needed: `~/.config/nix/nix.conf` with `extra-substituters = https://cache.nix.logos.co/public` and its `extra-trusted-public-keys` (taken from the Basecamp flake's `nixConfig`); without it Nix ignores the unsigned substitutes and tries to build from source. Allowed because the store is single-user.


## Problems hit

1. **Brief paths and layout were slightly wrong** (guest output dir, sequencer package path, `MAX_NUMBER_CHAINED_CALLS` location). The commands above are the corrected ones.
2. **`make build-programs` needs Docker**, and the cold image pull dominated the first build (about 1.4 GB over a 300-700 KB/s link). Docker was off when the task started; the user enabled WSL integration later.
3. **Sequencer build failed on `libclang`** (`bindgen` for rocksdb): "Unable to find libclang". Fix: the pip `libclang` wheel plus `LIBCLANG_PATH` and a gcc include dir. The Nix libclang (21.1.8) failed with `libc.so.6: version 'GLIBC_ABI_GNU2_TLS' not found` because host cargo `dlopen`s it against the older host glibc.
4. **`wallet` build failed on `pcsc-sys`** (`Could not find a PCSC library ... pkg-config command could not be found`). Fix: unpack the Ubuntu `.deb`s locally (see Environment). `LIBPCSCLITE_NO_PKG_CONFIG=1` does not help (it aborts the build script).
5. **`spel` at the guest-pinned rev cannot encode `i128` arguments** (`Serialization error: type mismatch: expected i128, got Raw("i128(0)")`). `initialize_program` has two `i128` gains. Workaround, no code change: `sed 's/"i128"/"u128"/g' stablecoin-idl.json > stablecoin-idl-u128.json` and pass gains `0`. This is only valid for non-negative values, and for 0 (what we used) it is bit-identical. A real negative gain needs a spel fix or a different client. Plan 2/3 should not depend on spel for signed integers.
6. **A default-owned account can sign for the stablecoin program only once.** Reusing instance A's `admin` as the instance B admin made the sequencer drop the transaction: log line `Transaction with hash d77d7ced... failed execution check with error: InvalidProgramBehavior(DeclaredAccountMissingFromOutput { account_id: ANrZ... }), skipping it`. This matches the comment in `lez-programs/programs/integration_tests/tests/stablecoin.rs` ("a default-owned owner works the first time it signs ... once the nonce bumps, the spel-framework output filter drops the unchanged default-owned post-state"). Running `wallet auth-transfer init` on the already-used account fails too. Fix: create the signer fresh and run `wallet auth-transfer init --account-id Public/<id>` *before* its first use (it becomes owned by the authenticated-transfer program); that account then signed two stablecoin transactions fine. **Every key that will sign more than one stablecoin-program transaction (admin, keeper, liquidator, bidder) must be auth-transfer-initialised first.** This must go into the Plan 2-4 runbooks and the app's account setup.
7. **Failed transactions are silent at the client.** `spel` and `wallet` print `Transaction NOT confirmed: Transaction not found in preconfigured amount of blocks` (or `Error: All pollers failed`) after about 3-4 minutes; the actual reason is only in the sequencer log. Always read `~/lez-spikes/s1/logs/sequencer.log` when a submit is "not confirmed".
8. **Transient network failures**: crates.io index/static, git clones in Nix. Retried unchanged each time; nothing was worked around or pinned differently.
9. **WSL session handling:** background jobs started with plain `nohup ... &` die when the invoking `wsl` call exits unless they run for a few seconds first; use `setsid nohup ... < /dev/null &`. (`run.sh` does.)

## Decision

- The toolchain works end to end with the pinned versions, with the environment fixes above. Nothing was unpinned.
- Multi-instance hosting by tagging the guest is viable: one `#[used]` static gives a distinct ImageID, a distinct PDA set, and a usable independent instance. The tag mechanism is the one Plan 2+ should use.
- The chained-call budget is comfortable: a hook-first liquidation uses about 4 of 11 executions, so `liquidate` can afford 2-3 extra token legs (for example a fee leg and a surplus-buffer leg) before touching the limit; stay at or below 10 if private execution is ever required.
- Signing accounts must be auth-transfer-initialised first (Problem 6); spel cannot encode signed ints (Problem 5).
- ADR: see ADR-018 in `docs/design-log.md`.
