# S8: LEZ v0.4.0-rc1 end to end (build, standalone sequencer, deploy, one fee-paying call)

Status: DONE (2026-10-31). Code in `spikes/s8_lez_v04/` (throwaway, outside the workspace).

## Question

Can we build LEZ v0.4.0-rc1 on this machine, run a standalone sequencer, deploy a program through
`program_loader`, and send a public transaction that pays its fee? What does 0.4 actually enforce, as opposed
to what the research (`docs/research/2026-10-31-lez-0.4-port-research.md`) and the design note
(`docs/v04-port-design.md`) assumed?

## Method

LEZ at tag `v0.4.0-rc1` (`1806e87`) cloned to `~/lez-spikes/lez-v04`, built in WSL (Ubuntu 24.04, 5 GB RAM + 4 GB
swap, `CARGO_BUILD_JOBS=2`, target `~/lez-target/v04`). Standalone sequencer on `127.0.0.1:3040` with the repo's
`lez/sequencer/service/networks/local.json`. The example `hello_world` guest (append the message bytes to this
program's actor state on the receiving account) deployed with the wallet, then called by
`spikes/s8_lez_v04/spike_call_hello.rs` (built as an extra bin of LEZ's `examples/program_deployment`), driven by
`spikes/s8_lez_v04/v04-spike.sh`.

## Findings

1. **Fees are mandatory.** A public transaction without a `FeeDeclaration` is refused at the RPC. LEZ's own
   `run_hello_world` example still builds one without a fee, so it no longer works.
2. **Admission.** Every public actor a transaction touches must be admitted: it signs, it already exists on
   chain, or the message carries `PublicAccountEvidence` (`Key(public key)` or `Pda { program, seed }`). An
   unadmitted actor makes the action revert with `UnadmittedPublicActor`.
3. **A revert costs the whole gas limit; success costs the metered cycles.** Confirmed on chain (this was
   `[unverified]` in the design note). The fee is `cycles × base_fee_exec + wire bytes × base_fee_stor + tip`, with
   `cycles = gas_limit` on a revert.
4. **Simulation predicts settlement**, provided the admitted set is right: `lee::simulate_public_transaction` with
   `Simulation { admitted_accounts: Some(..) }` reproduced both the revert and the success, with exact cycles.
5. **Deploy is `wallet program-loader deploy --elf --header --segments… --payer`** (the README's `deploy-program`
   is stale). The segment count comes from the ELF, not the file size; LEZ's example helper `deploy_program`
   uses the file size and panics ("splits into 3 segment(s) but 4 were supplied"). Worth an upstream issue.
6. **Accounts** read through `getAccount` as `actor_states` keyed by program address; the native balance is the
   state under `11111111111111111111111111111111`.

## Decision

- The SDK's transaction builder (design note §8, task 6) must: always attach a `FeeDeclaration`; attach
  admission evidence for every fresh actor (the engine's per-auction and vault PDAs as `Pda { program, seed }`;
  fresh user accounts by signature or `Key`); simulate with the exact admitted set before sending; and set
  `gas_limit` from the simulated cycles plus a margin, never a large default, since a revert burns all of it.
- Keepers and bidders who lose a race pay a whole gas limit (design note §4.3 b): keep it tight, and make the
  engine's pre-checks cheap and early so a stale bid fails in few cycles where possible.
- The 1.875 MiB program cap is not a constraint for the engine today.
- Next spike (S9): a minimal two-actor conversation on the standalone sequencer (a sync message with an exact
  `from` check and a PDA created with seed evidence) to measure the gas of the design note's building blocks.
