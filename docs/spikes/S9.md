# S9: a liquidation conversation on LEZ v0.4.0-rc1 (sync messages, reply, whole-actor checks, PDA)

Status: DONE (2026-10-31). Code in `spikes/s9_lez_v04/` (throwaway, outside the workspace). Builds on S8.

## Question

Do the design note's building blocks (`docs/v04-port-design.md` §4.1) work on a real 0.4 sequencer, and what do
they cost? Specifically: an engine asking a host to seize over a sync message, the host's reply standing in for a
return value, exact whole-actor `from` checks, and the engine opening a fresh auction PDA in the same transaction.

## Method

Two guests built in LEZ's `examples/program_deployment` guest crate with the local risc0 toolchain:
- `s9_engine.rs`: `Init` (config account signs); `Liquidate { host, auction_seed, amount }` at the config actor
  records a pending request and sends `Seize` to the host; `Seized { amount }` is accepted only if
  `from == Some(pending.host)` and the amount matches, then opens `Actor(for_public_pda(engine, seed), engine)`
  with `Open { config, amount }` and `with_pda_seeds([seed])`; `Open` is accepted only from exactly its config
  actor, only when authorized by the seed grant, and only once.
- `s9_host.rs`: `Init { engine, collateral }` (host account signs); `Seize { amount }` accepted only from exactly
  the bound engine actor, lowers the collateral and replies `Seized { amount }` to it.

So one `liquidate` is four executions: engine (config) → host → engine (config) → engine (auction PDA).
`spike_s9.rs` builds fee-paying transactions (optional `PublicAccountEvidence::Pda`) and simulates them with
`lee::simulate_public_transaction` against the live actor states; `s9.sh` drives the run. Same standalone
sequencer and dev payer as S8.

## Commands run

```bash
bash spikes/s9_lez_v04/s9.sh setup    # deploy both programs, create + init config and host (collateral 1000)
bash spikes/s9_lez_v04/s9.sh tests    # simulate, spoof, send, replay
spike_s9 liquidate <engine> <config> <host_prog> <host> 9 100 noevidence send
spike_s9 init-engine <engine> <rogue config>; spike_s9 liquidate <engine> <rogue config> ... sim
```

| Reference: one-execution `hello_world` (S8) | 7,555 cycles |

## Findings

1. **The conversation model works end to end.** Depth-first sync messages, a reply message in place of a return
   value, and checks on the replying side give the "ask, then verify the answer" pattern the design note relies
   on. A failure anywhere reverts the whole conversation, including state already set by earlier handlers.
2. **Whole-actor checks are necessary and sufficient here.** A second config of the same engine program is
   refused by `from == Some(bound actor)`; `from_own_program()` compares only the program and would have let it
   through. This confirms the design note's security rule (§4, "compare whole actors").
3. **A PDA opened by its own program needs no transaction-level evidence.** The `with_pda_seeds` grant on the
   message admits and authorizes it; `PublicAccountEvidence::Pda` is only needed for PDAs the transaction itself
   must admit (for example a PDA used as the root). This refines S8's decision.
4. **Cost.** About 12k cycles per execution here (borsh decode, a state write, one message). The design note
   estimates 15–20 executions for a full `liquidate` and 10–12 for a bid: roughly 180–240k and 120–150k cycles,
   or about 1.5–2M and 1–1.2M fee units at base fee 8. Both are far below the 10M gas cap per transaction. Real
   handlers do more work (oracle checks, `auction_core` maths), so this is a floor, not an estimate.
5. **Replay and stale requests fail early but expensively.** Every revert is charged the full gas limit (S8), so
   the SDK must simulate first and set a tight limit; the engine should order its checks so a stale request
   panics in its first handler.

## Decision

- Keep the design note's conversation patterns (§4.1) and the whole-actor rule; build the first port milestone on
  them.
- SDK: admission evidence only for accounts the transaction itself must admit; program-created PDAs are admitted by
  the program's seed grant.
- Measure again with real handlers once the engine shell exists, against the 10M cap and keeper economics.
- Next: start port milestone task 1–3 on lee rc1 in-process (design note §8), with the mock CDP host modelled on
  `s9_host.rs`.
