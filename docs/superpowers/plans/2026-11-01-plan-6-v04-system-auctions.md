## Proposed ADR-062 (recorded in `docs/design-log.md` by Task 9)

**Token holdings are one actor per (owner, definition).** *Context:* a holding was `T`'s single actor state on the owner's account, a map `definition → balance`; any `Transfer`/`NewDefinition { initial_to }` may credit any account, so anyone (not only the owner) can stuff junk definitions into a host vault, an auction vault or the buffer until `Sweep`/`Transfer`/`Burn`, which decode and re-encode the whole map, exceed the 10M gas cap. *Options:* (a) one holding actor per `(owner, definition)`; (b) debits whose cost does not depend on the map. (b) is not achievable on 0.4: a handler receives its whole `pre_state` and commits a whole post-state, so even a zero-decode patch costs O(state) cycles plus the state commitment. *Decision:* (a). The holding of `owner` for `definition` is the token actor at `pda(T, ["HOLDING", owner, definition])`, state `{ owner, definition, balance }`. The owner's own token actor `(owner, T)` is a stateless proxy: it accepts `Transfer`/`Sweep`/`Burn` only if `is_authorized` (signature or the engine's/host's PDA seed, unchanged for callers) and forwards an unseeded `Debit` to the holding, which accepts it only from `(o, T)` where `o` re-derives the receiver with the message's definition. `Credit` goes straight to the recipient holding with `T`'s `HOLDING` seed (a leaf), which admits a fresh holding without transaction evidence (S9 finding 3). *Consequences:* junk credited to an account lands in other actors and never changes the cost of a debit; nothing but `NewDefinition` ever writes `(X, T)`, so a PDA definition address can no longer be pre-blocked by a credit; one extra execution per debit; readers (engine Reads, harness, SDK) read `holding_actor(T, owner, def)`; holdings at zero keep their state.
